# AI 置信度透视插件（基于 Logprobs 的高亮工具）

## 1. 核心理念
利用大模型 API 返回的 `logprobs`（对数概率）数据，将 AI 生成文本中**“不确定”**（低概率）的 Token 进行可视化高亮，帮助用户快速定位潜在的“AI 幻觉”或逻辑薄弱点，从而提升人工审核效率。

## 2. 技术基石
- **依赖 API 参数**：`logprobs`（布尔值）与 `top_logprobs`（整数，返回 Top N 个候选 Token）。
- **目标平台**：**DeepSeek API**（`deepseek-v4-pro`、`deepseek-chat` 等模型明确支持 `Responses API` 与 `FIM API` 的 `top_logprobs` 参数）。
- **核心指标**：对数概率为负值，**越接近 0 表示模型越自信**。

## 3. 行业现状（为什么市场上少见此类大众插件）
虽然学术与开发者工具存在，但大众化插件稀缺，主要原因如下：
- **API 生态不统一**：OpenAI（o1 系列、新版 Responses API）、Google Gemini（反复无常且已部分移除）、Anthropic Claude（明确不支持）均存在支持缺失或弃用趋势。但鉴于dsh刚刚开放，deep seek还支持这个模式，这个插件还有制作的余地。
- **用户体验门槛**：原始数据为晦涩的负浮点数（对数概率），需复杂的 UI 映射（如热力图）才能被普通用户理解。但或许可以通过设定不同阈值等级来简化。
- **流式解析复杂**：处理流式输出的 JSON 碎片并实时渲染高亮存在技术挑战。

## 4. 现有参考工具（竞品分析）
| 工具名称 | 类型 | 核心逻辑 |
| :--- | :--- | :--- |
| **Prism** | Web 应用 | 本地运行小模型计算熵值，生成彩色热力图。 |
| **Logprob Visualizer** | 开发者工具 | 直接解析 OpenAI 兼容接口的 `logprobs`，展示备选 Token 图表。 |
| **Glassbox** | 浏览器插件 | 间接分析文本措辞（如闪烁其词），非基于 API 原生概率。 |
| **LLM BS Detector** | 浏览器插件 | 基于规则匹配“无依据自信”的套话模式。 |

> **结论**：直接基于 API `logprobs` 的工具多为**技术演示或研究工具**，而非大众日常插件。

## 5. 实用场景与使用策略（“威力”所在）
- **长短文的辩证关系**：
  - 长文（总结、报告）：热力图帮助快速跳过“蓝海”（高置信度常识区），仅审核“红点”（低概率突变点）。
  - **短文（事实查询、代码、参数）**：在处理“2024年诺贝尔奖得主”、“特定 API 函数名”时，**任何一个低概率红点都是致命错误的第一信号**，比长文更具核查价值。
- **黄金法则（避免误判）**：
  - **高概率 ≠ 正确**（AI 可能自信地胡说）。
  - **低概率 ≠ 错误**（文学创作中为求文采刻意选择低概率词）。
  - **核心策略**：**只看“突变点”**。即前后词均为高概率，中间突然出现极低概率的 Token，此处 100% 需要人工复核。

## 6. 针对 DeepSeek 生态的实施建议
- **插件命名**（要求：一看就懂）：
  - **首选**：**Logprobs Highlighter**（极客直白，专业感强）。
  - **备选**：Confidence Lens（稳重）、Doubt Tag（犀利）。
- **中文名**：概率高亮器 / 置信度显影剂。
- **Tagline**：*“逐词透视 AI 的底气，一眼揪出幻觉。”*
- **开发注意**：
  - 调用时务必开启 `top_logprobs=5`，观察 Top1 与 Top2 的差距。若差距极小（如 30% vs 25%），表明模型在此处犹豫不决。
  - 重点标记**数字、年份、人名、代码函数名**等低概率 Token。

## 7. 总结
本插件并非用于“阅读故事”，而是用于**“专业挑刺”**。通过将 DeepSeek 支持的 `logprobs` 数据转化为视觉信号，它能将人工审查从“通读全文”降维打击为“定点排雷”，极大提升代码审查、事实核查、合同审阅等场景的效率。
